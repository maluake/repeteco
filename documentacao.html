Repeteco

Documentação completa do projeto — código, telas, banco de dados, operação e roadmap de melhorias.

O Projeto

O Repeteco é uma plataforma web que conecta pessoas interessadas em moda sustentável, garimpo e cultura circular com brechós, sebos, antiquários e lojas de vinil de São Paulo. O site permite que qualquer pessoa descubra espaços por feed, mapa e busca — e que donos de espaços se cadastrem para aparecer na plataforma após aprovação da equipe.

🌐 Site público

Feed de brechos, mapa interativo, busca, cadastro e perfil do usuário

🏪 Painel do dono

Insights de visitas, editor do perfil da loja, preview do card público

👑 Painel admin

Fila de aprovação, moderação, visão geral da plataforma

🔐 Autenticação

Login, cadastro e recuperação de senha via Supabase Auth

Estrutura de Pastas

O projeto vive dentro de uma pasta chamada tcc/. Esta é a raiz pública — todos os arquivos que o browser acessa estão aqui.

tcc/ ├── index.html ← site público (início, mapa, feed) — SPA ├── style.css ← todo o visual do site público ├── app.js ← toda a lógica do site público ├── supabase.js ← cliente Supabase (carregado primeiro) ├── config.js ← configurações (chave Google Maps, etc.) ├── maps.js ← integração Google Maps ├── accessibility.js ← painel de acessibilidade ├── cadastro.html ← formulário para donos cadastrarem brechó ├── cadastro.js ← lógica do formulário de cadastro ├── supabase_migration.sql ← rodar UMA VEZ no Supabase SQL Editor ├── README-INTEGRACAO.md ├── dashboard.html ← DELETAR (versão antiga) └── dashboard/ ├── index.html ← painel admin + dono (página única) ├── dashboard.js ← toda a lógica do painel ├── dashboard.css ← visual do painel ├── login.html ← página de login do painel (redireciona) └── brechos.html ← DELETAR (funcionalidade migrada para index.html)
⚠️
Dois arquivos precisam ser deletados: tcc/dashboard.html (painel antigo na raiz) e tcc/dashboard/brechos.html (lista de brechós separada, já integrada ao painel). Deixá-los pode causar confusão e links quebrados.

Perfis de Usuário

O Repeteco tem três perfis distintos, controlados pelo campo role na tabela profiles:

👤 Usuário comum role: usuario

Qualquer pessoa que se cadastra no site. Não precisa de aprovação.

  • Navega pelo feed, mapa e busca
  • Cria conta e faz login
  • Curte e salva brechós
  • Edita o próprio perfil (nome, cidade, bio)
  • Pode enviar solicitação para cadastrar um brechó
  • NÃO acessa o painel (dashboard)

🏪 Dono de brechó role: dono

Usuário cujo brechó foi aprovado pelo admin. A role é atualizada automaticamente na aprovação.

  • Tudo que o usuário comum pode fazer
  • Acessa o painel em dashboard/index.html
  • Vê métricas do próprio brechó (visitas, curtidas, salvos)
  • Edita nome, descrição, contato, fotos e horário da loja
  • NÃO pode ver dados de outros brechós
  • NÃO pode aprovar ou recusar outros cadastros

👑 Administrador role: admin

Precisa ser definido manualmente via Supabase (ver seção Criar Admin).

  • Acessa o painel completo
  • Vê todos os brechós cadastrados e seus status
  • Aprova e recusa solicitações na fila
  • Vê métricas de qualquer brechó
  • Gerencia usuários da equipe
  • Acessa todos os dados da plataforma
ℹ️
Como a role é detectada: o app.js carrega o perfil do usuário logado e verifica o campo role. Se não for admin nem dono, também verifica se existe um brechó aprovado com aquele user_id — isso garante que donos com role desatualizada ainda consigam acessar o painel.

Tela: Início

É a primeira tela que o usuário vê ao acessar repeteco.com.br. Tecnicamente é uma SPA (Single Page Application) — todas as três abas (início, mapa, feed) são partes do mesmo arquivo index.html, mostradas e escondidas via JavaScript.

Seções da página inicial

Hero (foto de SP)

Imagem de fundo de São Paulo carregada do Unsplash. Puramente decorativa.

Barra de busca

Busca por nome, bairro ou categoria. Ao submeter, vai para a aba Feed e exibe os resultados. A busca usa ilike no Supabase — busca no banco, não apenas nos dados já carregados.

Carrossel "Espaços em destaque"

Mostra os 8 brechós mais recentes aprovados. Carregado dinamicamente do banco. Tem setas de navegação esquerda/direita. Clicar em um card abre a ficha do brechó.

Manifesto ("A sustentabilidade…")

Texto fixo de posicionamento da marca.

Bloco roxo "Explore o seu próximo rolê"

Grid de 8 bairros de SP. Cada bairro é um botão — ao clicar, vai para a aba Mapa com o filtro aplicado. Abaixo dos bairros ficam as "Novidades no feed": os 3 brechós aprovados mais recentes.

CTA "Divulgue o seu espaço"

Bloco roxo com dois botões: "quero divulgar" (vai para cadastro.html) e "criar conta" (abre modal de auth).

Rodapé

5 colunas com links: Descobrir, Estilos, Explorar, Institucional, Minha conta. A maioria dos links ainda não tem destino real (são href="#").

Tela: Mapa

Exibe os brechós aprovados em um mapa de São Paulo. Tem dois modos:

Modos do mapa

Modo Google Maps (ativo quando a chave está configurada)

Carrega o Google Maps real com pins. Cada pin representa um brechó que tem latitude e longitude preenchidos. Clicar no pin abre a ficha do brechó. Requer chave da API configurada em config.js e brechós com coordenadas no banco.

Modo SVG fallback (quando não há chave)

Um mapa ilustrativo em SVG com pins fixos nos brechós de demonstração. É o modo atual — funciona visualmente mas os pins não correspondem a brechós reais do banco.

Barra de busca do mapa

Filtra o mini-feed abaixo do mapa por nome ou bairro. Busca local nos dados já carregados.

Mini-feed "Mais recente no nosso feed"

Grid de 6 cards abaixo do mapa mostrando os brechós mais recentes. Clicar abre a ficha.

Tela: Feed

Grade estilo galeria editorial (inspirada no VSCO e Zara) com todos os brechós aprovados.

Componentes do feed

Filtros: todos / salvos / curtidos

Três botões no topo. "Todos" mostra todos os brechós aprovados. "Salvos" e "Curtidos" mostram apenas os que o usuário interagiu — exigem login. Se o usuário não estiver logado e clicar em "Salvos" ou "Curtidos", o modal de login abre.

Grid de 3 colunas (masonry)

Cada coluna tem um deslocamento vertical diferente (0px, 24px, 48px) para criar ritmo visual. As fotos são quadradas (aspect-ratio 1:1). Os botões de curtir (♡) e salvar (☆) aparecem ao passar o mouse sobre o card.

Estado vazio

Se não há brechós aprovados, mostra uma mensagem amigável com ícone e explicação.

💡
Como os brechos chegam ao feed: o app.js chama carregarBrechos() que faz SELECT na tabela brechos com filtro status = 'approved'. Apenas brechós aprovados aparecem. O array fica em memória como window.brechos.

Ficha do Brechó (Modal)

Abre ao clicar em qualquer card no feed, carrossel, mapa ou novidades. É um modal deslizante que aparece pela parte inferior da tela.

Conteúdo da ficha

Foto de capa

Imagem do campo foto_capa do banco. Se não houver, exibe o emoji padrão do brechó.

Tags / categorias

Chips com as categorias do brechó (ex: "brechó", "vintage", "anos 80").

Nome e localização

Nome do brechó e "📍 Bairro · Cidade".

Descrição

Texto livre descrito pelo dono no cadastro.

Botões de contato

WhatsApp (abre wa.me com mensagem pré-preenchida) e Instagram (abre perfil). Só aparecem se o brechó tiver esses dados preenchidos.

Ações: curtir, salvar, ver no mapa

❤️ curtir e 🔖 salvar exigem login. 📍 mapa fecha o modal e vai para a aba Mapa. Ao abrir o modal, um evento view é registrado na tabela brecho_eventos.

Login e Cadastro (Modal de Auth)

Modal centralizado que aparece ao clicar em "entrar" ou "criar conta" na navbar, ou ao tentar curtir/salvar sem estar logado.

Abas do modal

Aba "Entrar"

Campos de e-mail e senha. Botão "Entrar" chama doLogin(). Link "Esqueci minha senha" chama esqueceuSenha() — envia e-mail de recuperação via Supabase.

Aba "Criar conta"

Campos de nome, e-mail e senha (mínimo 6 caracteres). Botão chama doSignup(). Se o Supabase exigir confirmação de e-mail, mostra mensagem orientando o usuário a verificar a caixa de entrada.

Recuperação de senha

O usuário digita o e-mail na aba "Entrar" e clica em "esqueci minha senha". O Supabase envia um link de redefinição. Ao clicar no link, o usuário é redirecionado para index.html com um token na URL que o Supabase processa automaticamente.

⚠️
Confirmação de e-mail: o Supabase tem confirmação de e-mail ativa por padrão. Se estiver ativa, o usuário precisa confirmar o e-mail antes de fazer login. Para desativar durante desenvolvimento, vá em Supabase → Authentication → Settings → Email Confirm e desative.

Cadastrar Brechó (cadastro.html)

Página separada acessível pelo botão "quero divulgar" ou pelo link no rodapé. Qualquer pessoa pode preencher — não exige login.

Seções do formulário

Responsável

Nome, e-mail, WhatsApp e Instagram da pessoa responsável pelo espaço.

Sobre o espaço

Nome do espaço e descrição livre.

Categorias

Checkboxes: Brechó, Sebo, Antiquário, Moda vintage, Vinil, Colecionáveis. Múltipla seleção.

Localização

Cidade (pré-preenchida como "São Paulo"), bairro (obrigatório) e endereço completo.

Foto de capa

Campo de URL para imagem. Upload direto de arquivo ainda não está implementado — o dono deve colar uma URL de imagem.

O que acontece ao enviar

1

Validação

O cadastro.js verifica se nome, cidade, bairro, nome do responsável, e-mail e WhatsApp foram preenchidos.

2

Identificação

Se o usuário estiver logado, o user_id é salvo junto. Se não estiver, user_id fica null.

3

Insert no banco

Um registro é criado na tabela brechos com status = 'pending'. A policy RLS permite INSERT de qualquer pessoa com status=pending.

4

Mensagem de sucesso

Formulário é limpo e aparece a mensagem: "💚 solicitação enviada! Em até 5 dias úteis nossa equipe analisa…"

5

Fila de aprovação

O brechó aparece na fila do painel do admin como "pendente". O admin analisa e aprova ou recusa.

Como Acessar o Painel

O painel fica em tcc/dashboard/index.html. Ele redireciona automaticamente para index.html se o usuário não estiver logado ou não tiver permissão.

1

Acesso pelo site público

Se o usuário logado for admin ou dono, o botão "análises" aparece na navbar. Ao clicar, vai para o painel.

2

Acesso direto

Ir para /dashboard/index.html. O painel verifica a sessão automaticamente e redireciona se não autorizado.

3

Via login.html

A página dashboard/login.html tem um formulário de login simples que redireciona para dashboard/index.html após autenticar.

Painel Admin — Fila de Aprovação

Tela principal de moderação. Aqui o admin revisa cada solicitação e decide se aprova ou recusa.

Layout da fila

Lista de solicitações (painel esquerdo)

Cada item mostra foto/inicial, nome, localização, categoria, status e botões de ação. Clicar em um item seleciona para ver o detalhe.

Detalhe do brechó (painel direito)

Ao selecionar um brechó, aparece: foto, descrição, dados de contato, responsável, data do envio. Se pendente, botões de aprovar/recusar aparecem.

Analytics do brechó (no detalhe)

Para qualquer brechó selecionado (mesmo pendente), o admin vê visitas, cliques no mapa, curtidas, salvos e gráfico dos últimos 30 dias.

Fluxo de aprovação

1

Admin clica em "aprovar"

Chama aprovarBrecho(id) → alterarStatusBrecho(id, 'approved')

2

Status atualizado no banco

UPDATE na tabela brechos com status = 'approved'

3

Role do dono atualizada

UPDATE na tabela profiles do user_id do brechó com role = 'dono'

4

Brechó aparece no site

A policy RLS libera SELECT para brechós com status 'approved' — o brecho já aparece no feed público

5

Dono acessa o painel

Na próxima vez que o dono fizer login, o botão "análises" aparece na navbar e ele acessa o painel do dono

Painel do Dono — Perfil da Loja

Formulário completo para o dono editar os dados do brechó. Tem uma prévia ao vivo do card público.

Campos editáveis

Dados básicos

Nome da loja, categoria, bairro, cidade, endereço completo e descrição.

Contato

WhatsApp e Instagram. Ao salvar, esses dados aparecem nos botões de contato na ficha pública.

Foto de capa

URL da imagem principal. Se vazia, o feed mostra o emoji padrão. Se preenchida, aparece como foto no feed e na ficha.

Geocodificação automática

Se a chave do Google Maps estiver configurada, ao salvar o endereço, o sistema busca as coordenadas automaticamente e salva latitude/longitude no banco — o brechó aparece no mapa real.

Prévia ao vivo

À medida que o dono edita nome, categoria, bairro e foto, o card de prévia atualiza em tempo real para mostrar como ficará no feed público.

Como salvar

O botão "salvar alterações" chama salvarPerfilLoja(), que faz UPDATE na tabela brechos com os campos editados. A policy RLS verifica que o user_id do brechó corresponde ao usuário logado.

Código: supabase.js

Responsabilidade: criar a instância única do cliente Supabase e disponibilizá-la em window.supabaseClient.

const SUPABASE_URL  = "https://xhtjrmxkusuqmtpbebzv.supabase.co";
const SUPABASE_KEY  = "sb_publishable_...";

window.supabaseClient = window.supabase.createClient(
  SUPABASE_URL,
  SUPABASE_KEY
);
ℹ️
A chave usada é a anon/publishable key — é segura para ficar no frontend porque o acesso real é controlado pelo RLS. Nunca coloque a service_role key no frontend.

Código: cadastro.js

Responsabilidade: escutar o submit do formulário de cadastro de brechó e enviar os dados ao Supabase.

Pontos importantes

  • Não usa .select().single() após o insert — isso causaria erro 401 pela policy RLS
  • Funciona com ou sem usuário logado (user_id pode ser null)
  • Salva o campo foto_capa como URL (não upload de arquivo)
  • Coleta categorias dos checkboxes com name="categorias"
  • Exibe erros no #errorMessage, nunca via alert()
  • Requer campos: nome, cidade, bairro, responsavelNome, responsavelEmail, responsavelWhatsapp

Código: maps.js

Responsabilidade: carregar o Google Maps e posicionar pins dos brechós.

Funções exportadas

FunçãoO que faz
iniciarMapaGoogle(brechos)Carrega a API do Google Maps, cria o mapa centralizado em SP, plota pins nos brechós que têm latitude/longitude. Em caso de falha (sem chave), mantém o SVG de fallback.
localizarEnderecoGoogle(endereco)Geocodifica um endereço e retorna latitude, longitude, place_id e endereço formatado. Usada pelo painel do dono ao salvar o perfil.
⚠️
Mapa só funciona com chave configurada. Sem googleMapsApiKey em config.js, o maps.js cai silenciosamente para o SVG de fallback. Os pins do SVG são estáticos e não correspondem a brechós reais.

Políticas RLS

Row Level Security controla quem pode ler e escrever cada linha. Mesmo com a chave anon exposta no frontend, os dados ficam protegidos.

Resumo das políticas

TabelaOperaçãoCondição
profilesSELECTid = auth.uid() OU is_admin()
profilesINSERTid = auth.uid()
profilesUPDATEid = auth.uid() OU is_admin()
brechosSELECTstatus='approved' OU user_id=auth.uid() OU dono_id=auth.uid() OU is_admin()
brechosINSERTstatus='pending' (qualquer pessoa, mesmo anônima)
brechosUPDATEuser_id=auth.uid() OU dono_id=auth.uid() OU is_admin()
brechosDELETEuser_id=auth.uid() OU dono_id=auth.uid() OU is_admin()
curtidas / salvosSELECTuser_id = auth.uid()
curtidas / salvosINSERTuser_id = auth.uid()
curtidas / salvosDELETEuser_id = auth.uid()
brecho_eventosSELECTis_admin() OU brechó pertence ao usuário
brecho_eventosINSERTuser_id IS NULL OU user_id = auth.uid()

Triggers e Funções SQL

handle_new_user() — criação automática de perfil

Toda vez que um novo usuário se cadastra via Supabase Auth, o trigger on_auth_user_created chama esta função, que cria automaticamente um registro na tabela profiles com role="usuario".

CREATE TRIGGER on_auth_user_created
AFTER INSERT ON auth.users
FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();

is_admin() — verificação de permissão

Função SQL estável que retorna true se o usuário logado tiver role="admin" em profiles. Usada nas policies RLS para dar acesso total ao admin.

is_owner_of_brecho(id) — verificação de propriedade

Retorna true se o usuário logado for dono do brechó com o ID informado. Usada na policy de leitura de eventos.

Como Rodar o Migration

O arquivo supabase_migration.sql cria todas as tabelas, políticas, triggers e índices necessários. Deve ser rodado uma única vez em um banco vazio ou novo.

⚠️
O migration usa IF NOT EXISTS e ADD COLUMN IF NOT EXISTS em todos os comandos, então é seguro rodar novamente em um banco que já tem as tabelas — ele apenas ignora o que já existe.
1

Abrir o Supabase

Acesse supabase.com → seu projeto

2

Ir para o SQL Editor

Menu lateral → SQL Editor → New query

3

Colar o SQL

Copie todo o conteúdo de supabase_migration.sql e cole no editor

4

Executar

Clique em Run (atalho: Ctrl+Enter). Deve retornar "Success" em todas as linhas.

5

Verificar

Menu lateral → Table Editor → confirmar que as tabelas profiles, brechos, curtidas, salvos e brecho_eventos existem

O Que Falta Fazer — Roadmap

Lista priorizada do que precisa ser implementado para o Repeteco ser um produto profissional e lançável.

🔴 Urgente — sem isso o produto não funciona corretamente

  • Remover zoom: 1.25 do CSS — substituir por tamanhos de fonte maiores. Causa problemas em Firefox e Safari iOS.
  • Registrar eventos de view no app.js — sem isso, o gráfico de visitas do painel do dono ficará sempre zerado.
  • Corrigir o formulário duplicado em cadastro.html — dois <form id="storeForm"> aninhados é HTML inválido.
  • Implementar carregamento de curtidas e salvos ao fazer login — a função carregarInteracoes() precisa ser chamada após o login para persistir as interações entre sessões.
  • Busca no banco com ilike — a busca atual filtra apenas os dados já em memória.
  • Carrossel e novidades com dados reais — atualmente os cards são hardcoded no HTML.

🟡 Importante — para parecer profissional

  • Loading states — skeleton screens ou spinner enquanto os dados carregam.
  • Estado vazio amigável — quando feed, salvos ou curtidos estão vazios.
  • Botões de WhatsApp e Instagram no modal — a informação já existe no banco, falta exibir.
  • Recuperação de senha — link "esqueci minha senha" no modal de login.
  • Rodapé com títulos corretos — todas as colunas estão com o título "Categorias".
  • Formatação do dashboard.js — arquivo está minificado e impossível de manter.
  • Deletar arquivos obsoletos — tcc/dashboard.html e tcc/dashboard/brechos.html.
  • Design system consistente — o dashboard usa paleta diferente do site público.

🟢 Para lançar — obrigatório em produção

  • URL individual por brechó — ex: /brecho/garimpo-vintage. Sem isso, brechós não aparecem no Google.
  • SEO básico — meta description, Open Graph, title dinâmico, sitemap.xml, robots.txt.
  • Página "Sobre o Repeteco" — proposta de valor, história, contato.
  • Termos de uso e privacidade (LGPD) — obrigatório para coletar dados pessoais.
  • Hospedagem com domínio — Vercel/Netlify + repeteco.com.br.
  • Google Maps funcionando — chave configurada, brechós com coordenadas.
  • Upload real de fotos — Supabase Storage para foto de capa e fotos adicionais.
  • E-mail de confirmação configurado — template personalizado no Supabase.

⚪ Futuro — para escalar

  • Sistema de busca com filtros múltiplos (bairro + categoria + estilo)
  • Notificações por e-mail para o dono quando alguém curte ou salva
  • Blog/editorial com conteúdo sobre moda circular e sustentabilidade

Erros Comuns e Soluções

ErroCausaSolução
POST /brechos 401 (Unauthorized) Policy RLS bloqueando o INSERT Verificar se a policy brechos_insert_anon existe no Supabase. Rodar o migration completo.
42501 — row violates row-level security policy Mesma causa do 401, ou tentativa de SELECT após INSERT sem policy de SELECT Remover .select().single() após o INSERT no cadastro.js
Carrossel vazio / "undefined" Nenhum brechó aprovado no banco, ou erro na query Aprovar um brechó no painel admin ou verificar o console do browser por erros de rede
Mapa não aparece / fica SVG Chave do Google Maps não configurada em config.js Preencher googleMapsApiKey em config.js com uma chave válida
Dashboard redireciona para index.html Usuário não tem role=admin ou role=dono E não tem brechó aprovado Rodar UPDATE na tabela profiles para definir role=admin, ou aprovar um brechó do usuário
Login falha silenciosamente Supabase Auth com confirmação de e-mail ativa Desativar "Email Confirm" em Supabase → Authentication → Settings, OU orientar o usuário a confirmar o e-mail
Curtidas/salvos somem ao recarregar carregarInteracoes() não está sendo chamada após o login Chamar carregarInteracoes() dentro de carregarPerfil() após uiLogado()
Analytics zerado no painel do dono Evento "view" não está sendo registrado quando o modal abre Adicionar INSERT na tabela brecho_eventos dentro de openModal() no app.js
Site muito pequeno / zoom estranho zoom: 1.25 no CSS causando inconsistências Remover o zoom e aumentar font-size e espaçamentos nas propriedades individuais
Brechó cadastrado mas não aparece no feed Status é "pending" e a policy RLS bloqueia o SELECT para anônimos Admin precisa aprovar o brechó. Apenas brechós com status="approved" aparecem no feed.
💡
Dica de debug: abra o DevTools do browser (F12) → aba Network → filtre por "supabase". Todos os erros do Supabase aparecem ali com o código de erro exato e a mensagem completa. Isso é mais informativo que os erros que aparecem no console.
